# yahoo-bid-research（ヤフオク入札リサーチ）

ヤフオクで利益が取れそうな**アクセサリー / アパレル**をリストアップし、メルカリの売切相場から
**予想売値**と**入札提案価格**を出して一覧にするツール。Claude Code のスキルとして呼ぶ前提。

出力は3つ: `result.md`（人が読む）／`result.csv`（スプレッドシート用）／`candidates.json`（AIが目利きに使う）。

**入札はしない。** リストアップまで。外部送信（LINE/メール）機能も持たない。

---

## 導入（3手順）

### 1. フォルダを置く

スキルとして使うなら、このフォルダを丸ごと置くか、シンボリックリンクを張る。

```bash
ln -s "/Users/yuuya/claude code/yahoo-bid-research" ~/.claude/skills/yahoo-bid-research
```

`SKILL.md` がこのフォルダの直下にあるので、`~/.claude/skills/yahoo-bid-research/SKILL.md` として読まれる。
（配置は統括が行う。実行役はここを触らない。）

### 2. セットアップ

```bash
cd "/Users/yuuya/claude code/yahoo-bid-research"
./bin/ybr setup
```

`.venv` を作って `mercapi==0.4.2` を入れ、そのまま `selftest` が走る。
venv が作れない環境では、システムの `python3` に `mercapi` が入っていればそれを使う（自動判定）。
依存は **標準ライブラリ + mercapi のみ**。

### 3. 使う

```bash
./bin/ybr run                                   # アクセ+アパレル・利益率30%・上位20件
./bin/ybr run --category apparel --top 10
./bin/ybr run --brands "バーバリー,モンクレール" --margin 40
./bin/ybr run --keywords "ノースフェイス ヌプシ" --category apparel
./bin/ybr report                                # 直近の result.md を表示
./bin/ybr test                                  # テスト（ネットワーク不使用）
```

実行の最後に `result.md` のフルパスが出る。所要時間は既定で3〜5分（ヤフオク30回・メルカリ60回）。

## ⚠️ 既定値は「初期値」。本人未承認なので要調整

| 項目 | 初期値 | 根拠・調整の目安 |
|---|---|---|
| 出品送料（アクセ） | 300円 | ネコポス160〜210円＋梱包材の目安。実費に合わせる |
| 出品送料（アパレル） | 850円 | 宅急便（本人のアパレル講義の数値）。薄物なら下げる |
| メルカリ手数料 | 10% | 現行の販売手数料 |
| 目標利益率 | 30%（対売上） | `--margin` で変更 |
| 最低利益 | 2,000円 | これ未満の利益しか残らない価格では提案しない |
| 総額レンジ | 3,000〜150,000円 | `--min-total / --max-total` |
| 終了までの時間 | 60分〜72時間 | `--min-minutes / --max-hours` |
| ブランド語 | `keywords/*.txt` の38語 | **本人未承認の初期値**。売れている商材に入れ替える前提 |
| NG語・注意語 | `profiles/*.json` | 同上。誤爆したら直す |

**ブランド語と送料は必ず実運用の数字に合わせてから使うこと。** 初期値のままの結果は参考値。

編集するファイル:
- `keywords/accessory.txt` / `keywords/apparel.txt` — 検索語（1行1語・`#` でコメント）
- `profiles/accessory.json` / `profiles/apparel.json` — 送料・しきい値・NG語・ノイズ語

## 計算式（すべて「目安」）

```
n = メルカリ売切件数（自分で数えた件数。APIの num_found は使わない）
  n >= 8      → 確度「高」・係数 1.00（中央値は 1.5*IQR トリム後）
  3 <= n <= 7 → 確度「低」・係数 0.90
  n <  3      → 相場不明。採用しない（推測で埋めない）

fb = 相場クエリの縮退段数（0段 1.00 / 1段 0.95 / 2段 0.90）

予想売値     = floor(中央値 × n係数 × fb)
手取り       = 予想売値 − 手数料(10%) − 出品送料
ヤフオク送料 = 出品の送料（送料無料=0 / 未定=1,000円のペナルティ）
目標利益     = max(予想売値 × 利益率%, 2,000円)

入札提案価格   = floor100( 手取り − 目標利益 − ヤフオク送料 )
損益分岐入札額 = 手取り − ヤフオク送料      ← これ以上出すと赤字
見込み利益     = 手取り − ヤフオク送料 − 入札提案価格

採用条件 = 入札提案価格 >= 現在価格 かつ 入札提案価格 >= 1,000円
```

数値例: 予想売値10,000円・手数料10%・出品送料300円・ヤフオク送料0円・利益率30%
→ 手取り8,700円／目標利益3,000円／**入札提案価格5,700円**／見込み利益3,000円（目安）

## パイプライン

1. **ヤフオク検索** — 検索語ごとに1ページ100件。2.5〜4.0秒間隔。Chrome偽装UA（Python-urllib の既定UAは403になる）。
2. **一次フィルタ** — 総額レンジ／残り60分未満を除外／72時間超を除外／NG語（正規化後に照合）／同一実行内のID重複／直近7日の報告済み。
3. **メルカリ売切相場** — `mercapi` で `ITEM_TYPE_MERCARI` かつ `ITEM_STATUS_SOLD_OUT` かつ `is_no_price` でないものだけ。2.5秒間隔・24時間キャッシュ・クエリは6語→3語→2語と段階縮退。
4. **利益計算 → 採用判定 → 並べ替え**（見込み利益の降順、同点は終了が近い順）。
5. **出力** — `reports/<YYYYmmdd-HHMMSS>/` に `result.md` / `result.csv` / `candidates.json` / `run.log`。

## 終了コード

| コード | 意味 | そのときの振る舞い |
|---|---|---|
| 0 | 成功（採用1件以上） | |
| 1 | 使い方エラー（引数が不正など） | |
| 2 | 採用0件 | `result.md` に「採用0件」と不採用の内訳を書く。候補は作らない |
| 3 | 取得失敗 | 403 / 429 / 連続3回の通信失敗 / 日次上限 / メルカリ相場の全滅。`result.md` 冒頭に ⚠️ バナーを出す |

**コード3のときは結果を信用しない。** 数値を創作しないために即時停止している。

## 安全・正直さの作り込み

- ヤフオク取得は2.5秒以上の間隔・1実行30回まで・**日次120回まで**（`state/daily-budget.json`。
  accessory-profit-scout の予算ファイルとは別管理）。
- メルカリ照会は2.5秒以上の間隔・1実行60回まで・日次360回まで。
- 403 / 429 / 連続3回失敗で即時停止。リトライを連打しない。
- `mercapi` の例外は握り潰さず「相場取得失敗」として記録する（**「売切0件」と区別する**）。
- 相場0件は 0件として報告する（0埋め・推測をしない）。
- 出力テキストは制御文字・改行を無害化。**URLは必ず単独行**。出品タイトルに混入した
  `http(s)://...` は除去する（偽リンク行の注入防止）。
- 数値には必ず「目安」を付ける。相場の出典URL（メルカリ売切検索）を1件ごとに併記する。

## 既知の制限

1. **メルカリ検索は完全一致ではなく関連度順。** 売切件数 n が60件以上のときは別物が混ざりうる。
   その場合は `result.md` の「注意」に自動で警告が出るので、必ず相場URLを開いて目視確認する。
2. **管理番号が相場クエリに残ることがある**（例: `F431 Burberry London トレンチコート`）。
   「英数字の羅列だから管理番号」と決めつけて落とすと `M65` / `B-zero1` のような実在の型番まで
   消えるため、あえて落としていない。クエリと商品の不一致は目利き工程で見る。
3. **タイトルだけで判断している。** 商品説明本文・画像は見ていないので、真贋・状態・付属品は
   商品ページで確認が必要。
4. ヤフオクのHTML構造が変わると取得0件になる。その場合 `result.md` に
   「構造変化の疑い: <検索語>」が出る（黙って0件にしない）。
5. 検索は1語1ページ（最大100件）。終了が遠い出品が多い語では、72時間以内の候補が数件しか残らない。

## 開発

```bash
./bin/ybr test        # unittest 159件・ネットワーク不使用
./bin/ybr selftest    # 環境と設定の点検（ネットワーク不使用）
```

  メルカリは偽アダプタを注入する。

  あちらは1文字も変更していない。
