# yahoo-bid-research（ヤフオク入札リサーチ）

ヤフオクで利益が取れそうな**アクセサリー / アパレル**をリストアップし、メルカリの売切相場から
**予想売値**と**入札提案価格**を出して一覧にするツール。Claude Code のスキルとして呼ぶ前提。

出力は3つ: `result.md`（人が読む）／`result.csv`（スプレッドシート用）／`candidates.json`（AIが目利きに使う）。

**入札はしない。** リストアップまで。外部送信（LINE/メール）機能も持たない。

---

## 導入（3手順）

### 1. フォルダを置く

スキルとして使うなら、このフォルダを丸ごと置くか、シンボリックリンクを張る。

```bash
# このフォルダのパスを指定してシンボリックリンクを張る（配置先は配布環境に合わせる）
ln -s "$(pwd)" ~/.claude/skills/yahoo-bid-research
```

`SKILL.md` がこのフォルダの直下にあるので、`~/.claude/skills/yahoo-bid-research/SKILL.md` として読まれる。
（配置は統括が行う。実行役はここを触らない。）

### 2. セットアップ

```bash
cd ~/.claude/skills/yahoo-bid-research   # または、このフォルダを置いた場所
./bin/ybr setup
```

`.venv` を作って `mercapi==0.4.2` を入れ、そのまま `selftest` が走る。
venv が作れない環境では、システムの `python3` に `mercapi` が入っていればそれを使う（自動判定）。
依存は **標準ライブラリ + mercapi のみ**。

### 3. 使う

```bash
./bin/ybr run                                   # アクセ+アパレル・利益率30%・上位20件
./bin/ybr run --category apparel --top 10
./bin/ybr run --brands "バーバリー,モンクレール" --margin 40
./bin/ybr run --keywords "ノースフェイス ヌプシ" --category apparel
./bin/ybr report                                # 直近の result.md を表示
./bin/ybr test                                  # テスト（ネットワーク不使用）
```

実行の最後に `result.md` のフルパスが出る。所要時間は既定で3〜5分（ヤフオク30回・メルカリ60回）。

## ⚠️ 既定値は「初期値」。本人未承認なので要調整

| 項目 | 初期値 | 根拠・調整の目安 |
|---|---|---|
| 出品送料（アクセ） | 300円 | ネコポス160〜210円＋梱包材の目安。実費に合わせる |
| 出品送料（アパレル） | 850円 | 宅急便（本人のアパレル講義の数値）。薄物なら下げる |
| メルカリ手数料 | 10% | 現行の販売手数料 |
| 目標利益率 | 30%（対売上） | `--margin` で変更 |
| 最低利益 | 2,000円 | これ未満の利益しか残らない価格では提案しない |
| 総額レンジ | 3,000〜150,000円 | `--min-total / --max-total` |
| 終了までの時間 | 60分〜72時間 | `--min-minutes / --max-hours` |
| ブランド語 | `keywords/*.txt` の38語 | **本人未承認の初期値**。売れている商材に入れ替える前提 |
| NG語・注意語 | `profiles/*.json` | 同上。誤爆したら直す |

NG語の扱いで知っておくこと:
- 「風」「タイプ」は単独ではNGにしない。**ブランド名/ライン名の直後**に来る形だけNG
  （`ティファニー風` はNG、`春風コレクション` `Aタイプ` は通す）。ブランド語は
  `keywords/<category>.txt` から自動生成する。
- `K18GP` `18KGP` `SV925GP` `K14GF` `gold plated` など**くっついた品位+めっき表記**を
  正規表現で検出する。`K18 GPSケース` は誤爆しない。
- 模倣表現の判定には**英語表記**も使う（`TIFFANY風` `GUCCIタイプ` `Cartier調` を検出）。
  対応表は `profiles/*.json` の `brandAliases`（編集可。キー=検索語ファイル内の日本語表記）。
- **`brandTerms` は `keywords/<category>.txt` と `brandAliases` だけから作る。
  検索語ファイルに無いブランドの「◯◯風／◯◯タイプ」は検出しない**（新しいブランドを
  扱うときは検索語ファイルに追加する）。
- 否定表現の救済は「NG語が救済フレーズに**完全に含まれる**」ときだけ。
  `スーパーコピーライト` は救済しない。NG出現は**長いものから**判定するので
  `スーパーコピーではありません` は（`コピー` だけでなく）全体が救済される。
- **否定表現の救済は `allowPatterns`（正規表現）だけで行う。** `allowPhrases` に
  「GPではない」のような平文を置くと、二重否定（`GPではないわけではない`
  `虫食いはなくはない`）まで通ってしまう。`allowPatterns` は否定語の後ろが
  `わけ/訳/こと/とも/とは/が/はない/もない` のときは救済しない。
- `K18GPではありません` のようなくっついた否定も `allowPatterns` で救済する。
- GP/GF の型番除外は**ハイフン直結＋数字だけ**（`GF-01` `GP-02` は通す）。
  `K18GP 2.5g` `GP 2本セット` のように区切りを挟んだ数字は**めっき表記として除外する**。
- めっき系の `ngPatterns` は accessory / apparel の両方に入れている
  （バッグの金具・ベルトのバックル等の `金具 K18GP` 対策。実データ610件で誤爆0件）。
- NG語の区切り挿入による迂回を塞ぐ: カタカナは区切りを抜いた文字列でも照合
  （`レ プ リ カ` `コ・ピー`）。GP/GF は `G-P` `G・P` `G F` も検出（`GPS` は誤爆しない）。
  区切りを抜いた照合でも**同じ救済**を適用する（`ティファニー レプリカじゃない` は通す）。
- apparel は `リメイク` `虫食い` `シミあり/シミ有/シミ多/染み` をNGにしている
  （リメイクは原ブランドの相場と比較できないため）。`カシミヤ` `カシミア` は誤爆しない。
- **ダメージ系の扱い**: `ダメージ` は ngWords（除外）。`ダメージなし` `ダメージはありません`
  は allowPatterns の否定救済で通す。`ダメージ加工` `ヴィンテージ加工` は allowPhrases で通す。
  `ダメージ少` `ダメージ少なめ` は**除外**（ngWords に先に当たるので cautionWords に
  書いても到達しない。だから cautionWords には置いていない）。
- `--keywords` でカテゴリが判定できない語は、出品送料をアパレル側（850円＝高い側）にし、
  **NG語は両カテゴリの和集合**にする（送料だけ保守側でNG語が緩くなる穴を塞ぐため）。

**ブランド語と送料は必ず実運用の数字に合わせてから使うこと。** 初期値のままの結果は参考値。

編集するファイル:
- `keywords/accessory.txt` / `keywords/apparel.txt` — 検索語（1行1語・`#` でコメント）
- `profiles/accessory.json` / `profiles/apparel.json` — 送料・しきい値・NG語・ノイズ語

## 計算式（すべて「目安」）

```
n = メルカリ売切件数（自分で数えた件数。APIの num_found は使わない）
  n >= 8      → 確度「高」・係数 1.00（中央値は 1.5*IQR トリム後）
  3 <= n <= 7 → 確度「低」・係数 0.90
  n <  3      → 相場不明。採用しない（推測で埋めない）

fb = 相場クエリの縮退段数（0段 1.00 / 1段 0.95 / 2段 0.90）

予想売値     = floor(中央値 × n係数 × fb)
手取り       = 予想売値 − 手数料(10%) − 出品送料
ヤフオク送料 = 出品の送料（送料無料=0 / 未定=1,000円のペナルティ）
目標利益     = max(予想売値 × 利益率%, 2,000円)

入札提案価格   = floor100( 手取り − 目標利益 − ヤフオク送料 )
損益分岐入札額 = 手取り − ヤフオク送料      ← これ以上出すと赤字
見込み利益     = 手取り − ヤフオク送料 − 入札提案価格

採用条件 = 入札提案価格 >= 現在価格 かつ 入札提案価格 >= 1,000円
```

数値例: 予想売値10,000円・手数料10%・出品送料300円・ヤフオク送料0円・利益率30%
→ 手取り8,700円／目標利益3,000円／**入札提案価格5,700円**／見込み利益3,000円（目安）

## パイプライン

1. **ヤフオク検索** — 検索語ごとに1ページ100件。2.5〜4.0秒間隔。Chrome偽装UA（Python-urllib の既定UAは403になる）。
   検索語の消化順は**ブランド間ラウンドロビン**（上限が小さいとき先頭ブランドだけで埋まらない）。
2. **一次フィルタ** — 総額レンジ／残り60分未満を除外／72時間超を除外／NG語（正規化後に照合）／同一実行内のID重複／直近7日の報告済み。
   7日の報告済み履歴は**レポート出力が成功し、終了コードが 0 か 2 のときだけ**書く
   （コード3の部分結果を「報告済み」にすると、その商品が7日間再掲されなくなる）。
3. **メルカリ売切相場** — `mercapi` で `ITEM_TYPE_MERCARI` かつ `ITEM_STATUS_SOLD_OUT` かつ `is_no_price` でないものだけ。2.5秒間隔・24時間キャッシュ・クエリは6語→3語→2語と段階縮退。
4. **利益計算 → 採用判定 → 並べ替え**（見込み利益の降順、同点は終了が近い順）。
5. **出力** — `reports/<YYYYmmdd-HHMMSS>/` に `result.md` / `result.csv` / `candidates.json` / `run.log`。

## 終了コード

| コード | 意味 | そのときの振る舞い |
|---|---|---|
| 0 | 成功（採用1件以上） | |
| 1 | 使い方エラー（引数が不正・未知のカテゴリなど） | argparse の既定(2)ではなく1に統一している |
| 2 | 採用0件 | `result.md` に「採用0件」と不採用の内訳を書く。候補は作らない |
| 3 | 取得失敗 | 下表のいずれか。`result.md` 冒頭に ⚠️ バナーを出す |

コード3になる条件:
- ヤフオクが 403 / 429（**ページ位置に関係なく即停止**。2ページ目でも次の検索語へ進まない）
- ヤフオクの **HTTP試行**が3回連続で失敗（検索語単位ではなく試行単位で数える）
- メルカリが 403 / 429、またはメルカリ照会が3回連続失敗で中断（**有効な相場が取れていても3**）
- ヤフオク／メルカリの**日次上限**に途中で到達（部分結果なので成功扱いにしない）
- メルカリ相場が1件も取れず失敗だけが残った

**コード3のときは結果を信用しない。** 数値を創作しないために即時停止している。

### 「売切0件」と「未照会」は区別する

相場が無い理由を1つにまとめない。`candidates.json` の `comps_status` と
`excluded_kind` で必ず言い分ける（実測で混ざっていたため）。

| comps_status | 意味 | 不採用の区分 |
|---|---|---|
| `ok` | 相場が取れた | （採用判定へ） |
| `zero_hits` | 照会できたが売切0件 | 相場不明(メルカリ売切0件) |
| `budget_exhausted` | 予算切れで**照会していない** | 相場未照会(メルカリ予算切れ) |
| `fetch_error` | 通信・依存エラー | 相場未照会(取得失敗) |
| `aborted` | 連続失敗で照会中断 | 相場未照会(連続失敗で照会中断) |
| `blocked` | 403/429 で中断 | 相場未照会(メルカリにブロック) |
| `no_query` | タイトルから検索語が作れない | 相場未照会(クエリを作れず) |

## 安全・正直さの作り込み

- ヤフオク取得は2.5秒以上の間隔・1実行30回まで・**日次120回まで**（`state/daily-budget.json`。
  accessory-profit-scout の予算ファイルとは別管理）。**全ページ・全リトライを予算計上する**
  （`--pages 4` を1回分の予算で取らせない）。
- メルカリ照会は2.5秒以上の間隔・1実行60回まで・日次360回まで。
- 日次予算は `fcntl.flock` の下で「読み→判定→更新」を一体で行う（同時実行で残り1回を
  二重消費しない）。保存に失敗したときは止めず、`result.md` に ⚠️ 警告を出して続行する。
  **保存できなかった消費はメモリで数え続ける**（同一実行内で上限を超えられない）。
- 1実行の上限と日次上限が**同時に**尽きた場合も日次到達を記録する（exit3・履歴保存なし）。
- 403 / 429 / HTTP試行3回連続失敗で即時停止。リトライを連打しない。
- **メルカリの 403/429 は mercapi 内部の httpx クライアントに response フックを張って検出する。**
  mercapi 0.4.2 の `_search_impl` は status を見ずに `res.json()` するため、フックが無いと
  403 は「解析エラー」になってブロックを見逃す。フックを張れたかは `bin/ybr selftest` の
  「mercapi ブロック検出フック: OK/NG」行で確認できる。
- **フックを張れない環境では相場照会を1回も行わない（fail-closed）。**
  `run` は終了コード3で止まり、`result.md` に「403/429 を検知できない環境のため
  相場照会を中止しました」の ⚠️ バナーを出す。`selftest` もこの状態では失敗（非0）になる。
- メルカリの中断状態・連続失敗数は**実行全体で共有**する（403後は別カテゴリも照会しない）。
- メルカリ照会の予算判定は**キャッシュ確認の後**（キャッシュ命中は予算を消費しない）。
- `mercapi` の例外は握り潰さず記録する。**「売切0件」と「未照会」を必ず区別する**（上表）。
- 相場0件は 0件として報告する（0埋め・推測をしない）。
- **相場キャッシュには統計だけを保存する**（件数・中央値・四分位・外れ値除外前の件数）。
  クエリの縮退段数と掛け目は毎回その候補について決め直す（キャッシュで係数が外れないため）。
- 表示する `n` は外れ値除外後の件数。除外前の件数も `n=110（元115・外れ値除外）`の形で見せる。
- **n が8件未満で予想売値が現在総額の3倍を超える**ときは「乖離大・別物クエリ疑い」を
  自動で注意に出す（採用は維持。相場URLを目視確認する前提）。
- 出力テキストは制御文字・改行を無害化。**URLは必ず単独行**。出品タイトルに混入した
  `http(s)://...` は大文字スキーム（`HTTPS://`）も含めて除去する（偽リンク行の注入防止）。
- CSV は数式インジェクション対策済み（`=` `+` `-` `@` 始まりの文字列セルを無害化）。
- 指定した利益率がそのまま使えないときは黙って既定へ戻さず、`result.md` の見出しに
  「指定の90%は使用不可のため変更」と出す。`--margin nan` / `inf` は受け付けない。
- 数値には必ず「目安」を付ける。相場の出典URL（メルカリ売切検索）を1件ごとに併記する。

## 既知の制限

1. **メルカリ検索は完全一致ではなく関連度順。** 売切件数 n が60件以上のときは別物が混ざりうる。
   その場合は `result.md` の「注意」に自動で警告が出るので、必ず相場URLを開いて目視確認する。
2. **管理番号が相場クエリに残ることがある**（例: `F431 Burberry London トレンチコート`）。
   「英数字の羅列だから管理番号」と決めつけて落とすと `M65` / `B-zero1` のような実在の型番まで
   消えるため、あえて落としていない。クエリと商品の不一致は目利き工程で見る。
3. **タイトルだけで判断している。** 商品説明本文・画像は見ていないので、真贋・状態・付属品は
   商品ページで確認が必要。
4. ヤフオクのHTML構造が変わると取得0件になる。その場合 `result.md` に
   「構造変化の疑い: <検索語>」が出る（黙って0件にしない）。
5. 検索は1語1ページ（最大100件）。終了が遠い出品が多い語では、72時間以内の候補が数件しか残らない。
